# 08 · 转发与 VPN

## 本地服务转发（把对方手机里的服务“搬”过来）

`net/PortForward.java`。在**本机**监听一个端口，把连接通过已有的 nekosakana 链路
隧道到**对方本机**的某个服务，从而在本机 `127.0.0.1:本地端口` 访问对方的
`对方主机:对方端口`。

配置（设置页：「转发规则」）：

```
本地端口,对方主机,对方端口;本地端口,对方主机,对方端口;...
# 例：8080,127.0.0.1,80;5432,127.0.0.1,5432
```

协议帧：

- `tunnel.open{id,host,port}`：请求对方连接其本地服务。
- `tunnel.data{id,dir=req|res}` + body：字节流双向转发（16KB 分片）。
- `tunnel.close{id}`：关闭会话。

开启方式：设置页填规则 → 「开启转发」。所有其他应用即可通过 `127.0.0.1:本地端口`
访问对方服务，效果类似同一个局域网。

内置 FTP 桥（`net/FtpBridge.java`）：应用启动即监听 `127.0.0.1:2221`，在本机用
`ftp://127.0.0.1:2221` 即可访问**对方的 `/sdcard`**（无需任何配置，本机不对外提供 FTP）。
FTP 被动模式的数据端口是服务端临时分配的，普通 TCP 转发无法承载，因此桥会解析控制通道的
`227 PASV` / `229 EPSV` 响应，为每个数据端口动态建立子隧道。

## FTP 服务

`net/FtpServer.java`。**无需配置、随应用启动自动开启**，根目录是本机 **`/sdcard`**，
仅监听回环私有端口 `127.0.0.1:2222`。支持 PASV/EPSV、`LIST/NLST`、`RETR`、`STOR`、
`CWD/CDUP/PWD`、`SIZE`、`DELE`、`MKD`、`TYPE`、`FEAT`。匿名可登录，**不设置用户与密码**。

该服务不面向用户：它只是隧道在**对端**连接的数据源（对端 `FtpBridge` 连到本机 2222
即可读本机 `/sdcard`）。用户实际使用的只有一个入口：

- **对方 `/sdcard`**：`ftp://127.0.0.1:2221`（经 `FtpBridge` 自动隧道）。

## 可选 VPN（实验性）

`net/VpnBridge.java` 是一个 `VpnService`，仅接管独立子网 **10.66.0.0/24**，
用于为“局域网式访问”预留隧道接口，**不会影响其他应用正常上网**。

当前实现：建立 tun、接收数据保证接口活跃；**尚未实现完整的用户态 TCP/IP 转发**。
因此该开关目前是“预留能力”。真正跨设备访问对方本地服务请使用上面的**端口转发**。

### 为什么不做成完整的 tun TCP 转发

在 Android 上把 tun 的原始 IP 包还原为 TCP 流需要引入用户态协议栈（如 lwIP/tun2socks），
体积与稳定性代价较大。当前以应用层隧道（端口转发）达到等价目的：应用访问
`127.0.0.1:端口` 即可。若后续需要“应用直接访问对方 IP”，可在此基础上接入用户态协议栈。

## 与 Tailscale 的关系

以上服务都监听本机端口。若已登录 Tailscale，对方可直接通过 Tailscale 地址访问；
也可用端口转发在本地以 `127.0.0.1` 形式访问，二者可叠加使用。
