# 03 · 权限模型

本应用请求尽可能多的权限以覆盖各种场景，但**全部可选**：`PermsX.collect()` 会列出每项
是否已授权，未授权时对应功能在运行时不会被调用（`Control`、`ScreenShare`、`Overlay` 等
都会先检查可用性）。UI 的「授权」页即权限授权页，显示哪些还没授权。

## 运行时权限

| id | 权限 | 用途 |
| --- | --- | --- |
| `phone` | READ_PHONE_STATE / CALL_PHONE / ANSWER_PHONE_CALLS | 通话状态与拨号 |
| `contacts` | READ_CONTACTS | 联系人 |
| `calllog` | READ_CALL_LOG | 通话记录 |
| `location` | ACCESS_FINE/COARSE_LOCATION | 定位 |
| `location_bg` | ACCESS_BACKGROUND_LOCATION | 熄屏轨迹（10+ 单列） |
| `camera` | CAMERA | 相机 |
| `mic` | RECORD_AUDIO | 音频 |
| `sensors` | BODY_SENSORS | 身体传感器 |
| `activity` | ACTIVITY_RECOGNITION | 步数/活动识别 |
| `notification` | POST_NOTIFICATIONS | 通知（13+） |

## 特殊权限

| id | 权限 | 跳转 |
| --- | --- | --- |
| `storage` | MANAGE_EXTERNAL_STORAGE / WRITE_EXTERNAL_STORAGE | 所有文件访问 / 运行时 |
| `overlay` | SYSTEM_ALERT_WINDOW | 悬浮窗设置页 |
| `usage` | PACKAGE_USAGE_STATS | 使用情况访问设置页 |
| `battery` | REQUEST_IGNORE_BATTERY_OPTIMIZATIONS | 忽略电池优化 |
| `write_settings` | WRITE_SETTINGS | 修改系统设置 |
| `install` | REQUEST_INSTALL_PACKAGES | 未知来源安装 |
| `admin` | BIND_DEVICE_ADMIN | 设备管理员 |
| `accessibility` | BIND_ACCESSIBILITY_SERVICE | 无障碍 |
| `notif_listener` | 通知使用权 | 通知监听 |

## 提权能力

| id | 能力 | 说明 |
| --- | --- | --- |
| `root` | su | 若检测到 uid=0，ShellX 选 ROOT |
| `shizuku` | Shizuku/ADB | 服务在线且已授权时选 SHIZUKU |

## 提权优先级

`ShellX.backend()` 返回 `ROOT > SHIZUKU > APP`。凡需要系统级操作（冻结应用、
`svc wifi`、`settings put`、`input` 注入、`pm install` 等）都优先走该后端，
失败后再回退：

- 输入注入：shell `input` → 无障碍 `dispatchGesture`。
- 安装 APK：`pm install` → 系统安装器（FileProvider）。
- 冻结应用：设备所有者 `setApplicationHidden` → `pm disable-user`。
- 锁屏：设备管理员 `lockNow` → shell `input keyevent`。

## Shizuku 说明

`Shizuku.newProcess` 在 13.x 为私有方法，`ShellX` 通过反射调用；需在 Shizuku 中
对本应用授权。授权回调在「授权」页注册 `Shizuku.addRequestPermissionResultListener`。

## 权限页行为

- 顶部显示还有多少项未授权。
- 每项显示标题、状态与说明，并提供「授权 / 去授权 / 打开 Shizuku」等动作。
- 授权后返回应用会自动刷新（`onResume`/延迟重绘）。
