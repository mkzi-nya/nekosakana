# 01 · 架构总览

## 目标
在已登录 Tailscale 的两台 Android 设备之间建立点对点连接，提供远程查看、远程控制、
聊天、设备管理、状态读取、文件分发、端口转发与开放 API 等能力。所有权限均为**可选**：
未授权时相关功能在运行时不会被调用。

## 分层

```
app.nekosakana
├── App                    应用入口（初始化 Store/Config/Logx）
├── core
│   ├── Config             全局配置（SharedPreferences）
│   ├── Store              外部存储根目录（Android/nekosakana）
│   ├── Logx               实时文件日志 + 内存环形缓冲
│   ├── Archive            7z 归档（commons-compress + xz）
│   ├── ControlLog         操控日志
│   ├── CoreService        前台服务（链路/FTP/转发/定位记录）
│   └── BootReceiver       开机自启（受设置控制）
├── net
│   ├── NetInfo            Tailscale 地址识别、接口枚举、TCP 延迟
│   ├── Link               单条 TCP 链路的帧收发
│   ├── NetHub             连接中枢（监听+主动连接+心跳+去重）
│   ├── PortForward        本地端口 -> 对方本地服务 的隧道
│   ├── FtpServer          轻量 FTP 服务（回环 2222，根 /sdcard，隧道数据源）
│   ├── FtpBridge          FTP 感知隧道（本机 2221 -> 对方 /sdcard）
│   └── VpnBridge          可选 VPN（实验性）
├── caps                   能力层（每条能力都做了降级）
│   ├── ShellX             Root / Shizuku(ADB) / App 的 shell 执行
│   ├── AccessService      无障碍：手势注入、截图、前台应用跟踪
│   ├── Control            输入注入（优先 shell，其次无障碍）
│   ├── AdminReceiver      设备管理员
│   ├── PermsX             权限清单与请求动作
│   ├── Overlay            悬浮窗（消息/文件即时展示）
│   ├── ScreenShare        MediaProjection 采集 -> WebP 帧
│   ├── AudioShare         音频回放捕获 -> AAC/ADTS
│   ├── AudioPlayer        接收端 AAC 解码播放
│   ├── Media              位图编解码工具
│   ├── Chat               聊天记录
│   ├── UsageX             使用统计与前台应用
│   ├── DeviceStateX       设备状态读取与控制
│   ├── AppsX              应用列表/冻结/解冻/启动/卸载
│   ├── SensorsX           传感器枚举与读数
│   ├── LocationX          定位与轨迹
│   └── InstallerX         APK 安装
├── engine
│   └── Engine             协议分发引擎 + 请求/响应
├── api
│   └── ApiProvider        对外开放 API（ContentProvider.call）
└── ui
    ├── Ui                 UI 样式工具
    ├── MainActivity       主页/远程/会话/应用/设备/授权/日志/设置
    ├── LockActivity       锁定问答页
    └── ViewActivity       图片/视频/音频查看
```

## 启动流程

1. `App.onCreate`：初始化 `Store` → `Config` → `Logx`。
2. `MainActivity.onCreate`：启动 `CoreService`；若本机地址未知则异步探测；启动 1s 延迟轮询。
3. `CoreService.onStartCommand`：`startForeground`（dataSync|specialUse），
   启动 `NetHub`，自动启动 `FtpServer`（回环 `2222`，根 `/sdcard`）与 `FtpBridge`（本机 `2221` 访问对方 `/sdcard`），按配置启动 `PortForward`。
4. `NetHub.start`：开监听线程 + 主动连接线程 + 心跳线程。
5. 双方各自主动连接对方，收到入站连接后发送 `hello` 握手。

## 界面结构

- 底部**固定四个键**：主页 / 远程 / 会话 / 目录（不再是横向滚动）。
- 其余功能（授权 / 应用 / 设备 / 日志 / 设置）统一放在「目录」页入口。
- 主页「局域网」卡片：填入 Tailscale Key → 检测并大字显示本机内网地址；下方显示 FTP 地址。

## 数据流（以“查看对方屏幕”为例）

```
控制端 UI ── screen.start ──▶ 对方 Engine.handle
                                   │ 若无投影授权 → 拉起 LockActivity 之外的
                                   │ MainActivity(request_projection)
                                   ▼
                          ScreenShare.start → WebP 帧
                                   │ screen.frame（body=WebP）
                                   ▼
控制端 Engine.ScreenListener ──▶ MainActivity.ImageView（触摸映射回坐标）
                                   │ control{tap/swipe}
                                   ▼
                          对方 Control → ShellX(input) 或 无障碍手势
```

## 关键设计取舍

- **传输自研**：不依赖第三方即时通讯/推流库，帧协议简单可控，便于审计。
- **一切降级**：`ShellX` 自动在 Root→Shizuku→App 中选择后端；控制注入在
  shell 不可用时回退到无障碍手势；安装 APK 在特权不可用时回退系统安装器。
- **存储外置**：所有自身文件写入 `Android/nekosakana`，便于用户查看与 FTP 访问。
- **悬浮即时**：收到的消息/文件通过 `TYPE_APPLICATION_OVERLAY` 直接展示。
